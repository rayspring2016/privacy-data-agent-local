## 真实浏览器证据

使用独立 Chromium 会话和本地 8517 端口的 Streamlit 服务。
通过真实文件上传组件提交合成文件，而不是仅注入页面处理结果。

1. 上传 2 行员工 XLSX，处理成功，下载 ZIP；解压确认 8 个敏感值替换且文件清单正确。
2. 上传正常 XLSX 和损坏 XLSX，正常文件成功，损坏文件单独列出；页面可以继续操作。
3. 上传上一步输出的 XLSX 和匹配 JSON，执行恢复并下载；核对姓名、前导零工号和部门均恢复正确。
4. 页面显示 v1.15.2。测试中未观察到 JavaScript 页面错误。

单元格数据和下载内容已核对；没有宣称只凭成功提示就完成验收。

## 发现并修复

| 编号 | 触发条件与原问题 | 修复 |
| --- | --- | --- |
| QA-001 | 普通模式中，已知姓名重复出现在备注和公式字符串中仍为明文 | 两种模式都复用已识别身份；只改公式文字条件，保留引用和函数结构 |
| QA-002 | 已知身份残留于批注、页眉页脚、文件作者信息 | 附加文本统一使用本次映射，恢复时走相同覆盖范围 |
| QA-003 | 图表标题/字符串缓存、薪资数值缓存残留原始值 | 文本缓存替换；敏感数值引用缓存清除；不可安全转换的独立数值提示核验 |
| QA-004 | 左右结构表单处理成功但 row_count 为 0 | 按实际非空数据行统计 |
| QA-005 | 收起的预览仍执行，坏 XLSX 让整批页面抛异常；预览未反映开关 | 预览单文件报错提示并继续；按当前选项标记处理方式 |
| QA-006 | 移除上传的历史匹配文件后，session_state 仍保存旧文件 | 上传组件为空时同步清除历史文件引用 |
| QA-007 | 打包脚本误删已跟踪的本地 Streamlit 配置 | 保留配置并在发行校验中确认配置一致；同步 CHANGELOG |

## 固定验收命令

```sh
uv run --extra dev pytest -q
bash tools/build_app.sh
uv run --extra dev python tools/verify_release.py
```

`verify_release.py` 校验 ZIP 完整性、安全路径、无运行数据、版本号、源码文件集合和逐字节内容、
本地网页配置；若存在 sha256 文件则核对校验值。
随后明确切换到解压后的源码路径运行完整测试。
测试样例使用项目 tests/fixtures，CLI 和网页测试都导入发行包中的模块。

## 验收边界

- 未获得本次用户报错的原始工作簿；透视表错误使用最小真实 XLSX 结构复现。
- 未在 Windows 上双击安装/启动，未在 Excel/WPS/Numbers 原生客户端打开并重算；没有将 Linux/macOS 的测试当作 Windows 认证。
- 未覆盖扫描图片/PDF 的 OCR、宏工作簿、嵌入 OLE 对象、Excel 所有图表/外接数据源/扩展节点、恶意压缩包或 200 MB 大文件上限。
- Word/PDF 的覆盖以现有文本用例为准，不能据此保证所有页眉、绘图、图片文字和文档元数据都被脱敏。
- 姓氏启发式依然可能误报或漏报；本轮附加文本处理只复用已识别实体，不承诺识别任意文字中的全部个人信息。
- 对已识别姓名出现在 sheet 名或图表引用名称的情况，选择提示调整后重试，避免直接改名破坏引用。
